# 03. 데모 시나리오 및 사용자 경험 플로우 (Demo Scenarios & User Flows)

본 문서는 해커톤 심사위원 대상의 **3~5분 라이브 피칭 및 시연**에서 심사위원의 탄성을 자아낼 4가지 핵심 데모 시나리오와 사용자 인터랙션 플로우(UI/UX)를 정의합니다.

---

## 🎬 1. 해커톤 4대 킬러 데모 시나리오 (Killer Demo Scenarios)

### 🚇 시나리오 1. 대중교통 환승역 혼밥 퀵스탑 (국내 최초 시도 ⭐)
* **상황:** 강남역에서 회의를 마치고 신분당선을 타고 판교역 오피스로 복귀하는 20대 직장인.
* **사용자 프롬프트:**
  > *"강남역에서 판교역 신분당선 타고 갈 건데, 중간에 환승하거나 잠깐 내려서 15분 컷으로 먹고 갈 만한 담백한 돈까스나 소바집 추천해줘. 1시간 안에 판교 도착해야 해."*
* **기존 지도 앱의 비참한 현실:**
  * 네이버/카카오 지도에서 지하철 길찾기를 하면 양재역이나 판교역 주변을 일일이 따로 검색해야 함. 어디가 3번 출구 바로 앞인지, 음식이 빨리 나오는지 알 방법이 없음.
* **WayBite의 라이브 시연 동작:**
  1. **ODsay 환승 그래프 분석:** 신분당선 이동 궤적 상의 유일한 환승 거점인 **'양재역'**을 최적 중간 노드로 자율 선정.
  2. **보행 시간 + 음식 조리 시간 연산:** 
     * 양재역 3번 출구에서 도보 120m (2분).
     * 리뷰 RAG 분석 결과: *"키오스크 주문 후 4분 만에 서빙"* 키워드 감지 (조리속도 지수 0.95).
  3. **시간 검증:** 양재역 도착(12:42) $\to$ 식당 도착(12:44) $\to$ 식사 완료(13:05) $\to$ 판교역 최종 도착(13:22) $\rightarrow$ **총 여정 52분으로 1시간 이내 완벽 충족!**
  4. **심사위원 임팩트:** 지하철 경로 상에서 '환승/하차 식사'를 완벽하게 타임라인으로 풀어내는 국내 유일무이한 UX.

### 🚗 시나리오 2. 고속도로/주행 중 브레이크타임 회피 (Temporal Safety Guardrail)
* **상황:** 서울에서 양양/속초로 오후 1시 30분에 출발하는 주말 드라이브 여행객.
* **사용자 프롬프트:**
  > *"서울 잠실에서 속초 해수욕장 가는 길에 들를 만한 막국수 맛집. 춘천/가평 부근에서 먹고 싶어."*
* **시간 불일치 참사 시뮬레이션 (기존 앱):**
  * 기존 앱은 평점 4.8인 유명 A 막국수집을 추천함. 
  * 하지만 잠실에서 가평 A식당까지 주말 정체로 70분 소요 $\rightarrow$ 도착 예정 시간은 **14:40**.
  * 그러나 A식당의 **점심 라스트오더는 14:30**, 브레이크타임은 15:00부터! $\rightarrow$ **도착하자마자 퇴짜 맞고 헛걸음 발생.**
* **WayBite의 라이브 시연 동작:**
  1. $T_{\text{ETA}}$(14:40)와 A식당의 라스트오더(14:30)를 실시간 대조하여 **A식당을 🔴 [자동 탈락] 처리하고 탈락 사유를 시각적으로 노출**.
  2. 대안으로 14:35에 도착해도 라스트오더가 15:00까지이고 브레이크타임이 없는 춘천의 B 막국수집(우회 시간 단 +6분)을 🟢 **[안전 보장]** 뱃지와 함께 추천!
  3. **심사위원 임팩트:** "내가 겪었던 헛걸음 문제를 AI가 알아서 방어해 주는구나!"라는 강한 현실 공감대 형성.

### 🚶 시나리오 3. 도보 & 자전거 뚜벅이 힐링 코스 (Micro-Mobility)
* **상황:** 성수동에서 서울숲을 지나 뚝섬 한강공원으로 따릉이(자전거)를 타고 가는 커플.
* **사용자 프롬프트:**
  > *"성수역에서 뚝섬유원지 쪽으로 자전거 타고 가는데, 오르막길 없고 자전거 잠깐 세워두기 편한 테라스 베이커리 카페 있어?"*
* **WayBite의 라이브 시연 동작:**
  1. 자전거 도로 네트워크 및 등고선 고도 데이터를 분석하여 급경사 구간을 우회.
  2. 리뷰 RAG에서 *"가게 앞 테라스에 자전거/킥보드 거치 공간 넉넉함"* 스니펫을 감지하여 1순위 추천.

### 🎛️ 시나리오 4. 파레토 인터랙티브 트레이드오프 슬라이더 (Visual Wow Factor)
* **시연:** 화면 상단의 슬라이더를 실시간으로 드래그:
  * **[우회 시간 최소화 (Fast Focus)]:** 우회 시간 +3분, 평점 4.1의 역전 국밥집 즉시 핀 표시.
  * **[맛집 퀄리티 극대화 (Gourmet Focus)]로 슬라이더를 우측으로 땡김:** 
    * 지도 상의 오렌지 경로가 살짝 넓어지면서(+14분 우회), 식객 허영만의 백반기행에 나온 평점 4.7의 숨겨진 노포 맛집으로 핀이 매끄러운 트랜지션 애니메이션과 함께 교체!
  * **심사위원 임팩트:** "시간 vs 맛"의 트레이드오프를 사용자가 직관적으로 체감할 수 있는 인터랙티브 UI의 극치.

## 💡 3. 심사위원 Q&A 예상 질문 및 방어 논리 (Defense Script)

* **Q1. "네이버 지도나 카카오맵이 이 기능을 안 만드는 이유가 뭔가요? 그들이 만들면 어떻게 하나요?"**
  * **A:** 기존 지도 앱은 **'포털형 지도'**로서 출발지 검색과 목적지 검색이라는 전통적인 검색 패러다임에 갇혀 있습니다. 특히 대중교통 환승 그래프와 음식점 조리시간/브레이크타임을 결합하는 연산은 기존의 단순 DB 쿼리 방식으로는 불가능하며, **시공간 제약조건 최적화 엔진과 LLM 에이전트 파이프라인**이 필수적입니다. 향후 B2B API 형태로 티맵이나 카카오모빌리티에 플러그인될 수 있는 고부가가치 엔진입니다.

* **Q2. "식당의 음식 조리 시간이나 혼밥 가능 여부는 정형 데이터가 없는데 어떻게 신뢰하나요?"**
  * **A:** 정형 데이터가 없기 때문에 **비정형 리뷰 RAG(Retrieval-Augmented Generation)** 기술을 사용합니다. Google Places 및 블로그 리뷰 수백 개에서 '주문 후 서빙 시간', '1인 식사 분위기' 문장을 추출하고, LLM이 신뢰도 점수를 매긴 뒤 근거 문장(Evidence Snippets)을 사용자 화면에 그대로 보여주어 환각을 방지하고 투명성을 제공합니다.
